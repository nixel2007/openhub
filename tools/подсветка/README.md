# Движок подсветки кода

Страница пакета раскрашивает в README блоки кода с языком `bsl` или `1c` движком
[shiki](https://shiki.style) с одной грамматикой BSL (вместе с языком запросов внутри строк)
и темой `css-variables`. Здесь этот движок собирают и проверяют.

## Что куда уезжает

| Файл | Что это |
| --- | --- |
| `src/статика/подсветка/shiki-bsl.mjs` | движок: минифицированный ES-модуль с одной функцией `токены(код, язык)` |
| `src/статика/подсветка/LICENSE` | лицензии всего, что вошло в движок, и происхождение грамматики BSL |
| `src/статика/openhub-highlight.js` | клей: ванильный скрипт без сборки — находит блоки и грузит движок |
| `src/статика/openhub.css`, раздел о подсветке | цвета: переменные `--shiki-*` из палитры кита |

Движок лежит в репозитории готовым файлом: в образе хаба и в джобах OneScript node нет,
хаб отдаёт статику как есть, а с чужого CDN его не взять — хаб работает и в закрытом
контуре. Доверие к минифицированному файлу держит тест воспроизводимости: сборка
из `package-lock.json` обязана дать закоммиченные файлы байт в байт.

Текст лицензии грамматики BSL лежит здесь же, в `лицензия-грамматики-bsl.txt`: грамматика
приезжает внутри `@shikijs/langs-precompiled`, и своей лицензии у неё там нет.

## Пределы

Код README чужой, и раскрашивается он в главном потоке вкладки, поэтому работа ограничена:

- строку длиннее 1000 символов движок не разбирает — она остаётся одним куском текста;
- над одной строкой грамматика думает не дольше 50 мс, дальше строка докрашивается как есть;
- блок длиннее 20 000 символов клей движку не отдаёт вовсе;
- блоки раскрашиваются по одному за задачу, и между ними вкладка отвечает.

Первый разбор собирает грамматику, а это дольше предела на строку, поэтому движок
разогревается при загрузке: иначе первая строка на странице приходила бы бесцветной.

## Пересобрать

```bash
cd tools/подсветка
npm ci          # точные версии из package-lock.json
npm run build   # пишет shiki-bsl.mjs и LICENSE в src/статика/подсветка
```

Правка `движок.js`, `собрать.js` или текста лицензии грамматики без пересборки роняет тест
воспроизводимости: это и есть напоминание закоммитить новый движок.

## Обновить shiki

1. Поднять версии `@shikijs/*` в `package.json` — точными, без `^`, все четыре одинаковыми.
2. `npm install` — обновит `package-lock.json`.
3. `npm run build`, затем `npm test`.
4. Закоммитить `package.json`, `package-lock.json`, движок и его `LICENSE` одним коммитом.
   Адрес движка на странице несёт отпечаток содержимого, поэтому кэш читателей
   сменится сам.

## Тесты

```bash
npm test
```

Они же идут в CI джобом «Подсветка кода» и стерегут четыре вещи:

- `движок.test.js` — закоммиченный движок размечает BSL: ключевые слова, константы, строки,
  комментарии, запрос внутри строки, псевдоним `1c`; текст из токенов собирается без потерь,
  строка длиннее предела не разбирается, а первая строка холодного движка — разбирается;
- `клей.test.js` — клей в DOM (linkedom) раскрашивает только блоки `bsl` и `1c` внутри
  `[data-highlight]`, по одному за задачу; без таких блоков движок не грузит, блок длиннее
  предела ему не отдаёт, отказ движка оставляет код текстом, а разметка из кода
  не исполняется;
- `стили.test.js` — лист хаба объявляет на `[data-highlight]` каждую переменную, которую
  тема может выдать токену, и только из палитры кита;
- `сборка.test.js` — воспроизводимость движка и полнота его `LICENSE`.

## Браузеры

Предкомпилированные регулярные выражения грамматики используют флаг `v`: Chrome 112+,
Firefox 116+, Safari 17+. В браузере старше движок не загрузится, и код останется обычным
текстом: подсветка — только улучшение, страница без неё та же.
